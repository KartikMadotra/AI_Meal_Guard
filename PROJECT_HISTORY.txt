======================================================================
                     AI MEALGUARD - PROJECT HISTORY
======================================================================
This document contains a chronological record of all major events,
decisions, and structural changes made to the AI MealGuard project.
It will be updated whenever a major change occurs.

----------------------------------------------------------------------
PHASE 1: Inception & Blueprinting
----------------------------------------------------------------------
- The project was conceived as "AI MealGuard", an AI-powered smart 
  monitoring system for school meals, designed to align with the UN's 
  SDG-2 (Zero Hunger) goals.
- A comprehensive architectural blueprint was created 
  (AI_MealGuard_Blueprint.html / Blueprint.txt) outlining the feature 
  set, age-based nutritional rules, and system design.

----------------------------------------------------------------------
PHASE 2: Frontend & UI/UX Development
----------------------------------------------------------------------
- A vibrant, modern frontend was built from scratch using HTML/CSS/JS.
- Mockups and UI components were iteratively tested and refined to create 
  a premium user experience with micro-animations and smooth gradients.
- Core pages were implemented:
  1. The live camera / image upload scanning interface.
  2. The analytical dashboard displaying historical statistics and 
     SDG-2 compliance scoring.
- NOTE: Per user request, the frontend code was later removed from the 
  workspace to focus exclusively on the backend API and AI logic.

----------------------------------------------------------------------
PHASE 3: Initial Backend & AI Integration (V1)
----------------------------------------------------------------------
- The first iteration of the backend was built using FastAPI, structured 
  across multiple folders (api, ai, models, nutrition, scoring).
- A YOLOv8 segmentation model (yolov8n-seg.pt) was provided by the user. 
  This model was trained on the IIIT-Delhi Indian Thali dataset.
- Basic nutritional databases and age-group requirements were integrated 
  to support the scoring engine.

----------------------------------------------------------------------
PHASE 4: The Label Mismatch Investigation
----------------------------------------------------------------------
- A critical bug was discovered: the AI model drew perfect segmentation 
  boundaries around food items but output completely wrong class names.
- Investigation revealed that the model was trained using a `data.yaml` 
  file containing a 50-class list from an older version of the dataset.
- However, the actual image masks used during training were encoded 
  using a different 41-class mapping (`index_map.json` / `your_dataset_big_2.py`).
- This misalignment caused a permanent deterministic "label shift" during 
  inference (e.g., Mask ID 1 was Bottle-gourd-curry, but data.yaml 
  labeled ID 1 as Aloo-Dry-fry).

----------------------------------------------------------------------
PHASE 5: Forensic Audit & Backend Rewrite (V2)
----------------------------------------------------------------------
- The scattered V1 backend was deleted and consolidated into a clean, 
  robust 4-file structure:
  1. `main.py` (FastAPI and endpoints)
  2. `database.py` (SQLite models)
  3. `ai_service.py` (YOLO inference and model loading)
  4. `nutrition_service.py` (Food data, age rules, scoring engine)
- A dynamic **Weight Estimation System** was implemented: it calculates the 
  exact pixel area of the YOLO segmentation masks and multiplies it by 
  a food-specific density factor to accurately estimate portion sizes in grams.

----------------------------------------------------------------------
PHASE 6: Finalizing the AI Model [CURRENT]
----------------------------------------------------------------------
- The user successfully retrained the YOLOv8 model (`best.pt`) on Kaggle 
  using the corrected 41-class `data.yaml` generated by our scripts.
- The new `best.pt` model was imported into the project, and the old 
  `yolov8n-seg.pt` model was removed.
- Because the new model natively outputs the correct food classes, the 
  complex "Unscrambler" logic was permanently removed from `ai_service.py`, 
  making the code significantly cleaner and faster.
