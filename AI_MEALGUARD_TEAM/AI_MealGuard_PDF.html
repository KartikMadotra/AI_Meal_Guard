02 • PROBLEM

Problem Statement

India's Mid-Day Meal Scheme (PM POSHAN) serves over 12 crore children daily. However, monitoring the nutritional quality of each plate manually is nearly impossible at this scale. Teachers and staff do not have the tools to verify whether each child's plate meets the recommended dietary standards for their age group.

flowchart LR A["🏫 School Kitchen"] --> B["🍽️ Plate Served"] B --> C["👁️ Manual Check?"] C --> D["❌ No Tools"] C --> E["❌ No Standard"] C --> F["❌ No Record"] D --> G["❓ Unverified Nutrition"] E --> G F --> G

🔴 The Challenges

  • Manual observation is time-consuming and inconsistent
  • Portion sizes are difficult to estimate visually
  • Nutrition calculations require separate expertise
  • There is no automated record of what was served
  • Historical trends are impossible to maintain manually
  • Different age groups need different nutritional targets

🟢 Our Response

  • Camera-based meal capture (file upload or webcam)
  • AI-powered food detection and segmentation
  • Automatic quantity estimation from pixel area
  • Nutrition lookup against a verified database
  • Age-aware comparison with ICMR-NIN benchmarks
  • Score + explanation + recommendations
  • Full meal history and analytics dashboard
Important: This is a monitoring and screening prototype, not a laboratory food-safety test. We never claim to physically weigh food.

09 • FACIAL RECOGNITION

How Facial Recognition Works

Our system uses the face_recognition Python library (built on dlib's deep learning model) to create and match 128-dimensional face embeddings. Here is exactly how it works:

flowchart TD A["📷 Webcam captures frame"] --> B["Base64-encode image"] B --> C["Send to /api/students/check_face or /recognize"] C --> D["decode_base64_image: PIL → RGB → numpy array"] D --> E["face_recognition.face_locations: Find bounding boxes"] E --> F{"Face Found?"} F -->|No| G["Return face_detected: false"] F -->|Yes| H["face_recognition.face_encodings: Extract 128D vector"] H --> I["Registration: Store encoding as JSON in students.csv"] H --> J["Login: Compare with ALL stored encodings"] J --> K["face_recognition.face_distance: Euclidean distance"] K --> L{"Best distance ≤ 0.6?"} L -->|Yes| M["✅ Match found — return student"] L -->|No| N["❌ No match"] 
# face_utils.py — Key Functions

def get_face_encoding(base64_img):
    img = decode_base64_image(base64_img)         # PIL → RGB → numpy
    face_locations = face_recognition.face_locations(img)
    if not face_locations: return None
    encodings = face_recognition.face_encodings(img, face_locations)
    return encodings[0].tolist()                   # 128-dimensional list

def find_matching_student(unknown_encoding, students, tolerance=0.6):
    known_encodings = [np.array(s["face_encoding"]) for s in students if s.get("face_encoding")]
    distances = face_recognition.face_distance(known_encodings, np.array(unknown_encoding))
    best = np.argmin(distances)
    if distances[best] <= tolerance: return student_ids[best]
    return None
Auto-Capture Flow: The frontend polls the webcam every 1 second. Each frame is sent to /api/students/check_face (registration) or /api/students/recognize (login). When a match is found, the modal auto-closes and the student ID is auto-filled.
10 • AI CONCEPT

Computer Vision Explained

Computer Vision is a branch of AI that enables machines to "see" and extract useful information from images. Our system uses it to answer 3 questions about every plate:

flowchart LR A["📸 Meal Image"] --> B["🤖 Computer Vision"] B --> C["❓ What food is this?"] B --> D["❓ Where is it on the plate?"] B --> E["❓ How much area does it cover?"] C --> F["Food Class + Confidence"] D --> G["Bounding Box + Polygon Mask"] E --> H["Pixel Area → Estimated Weight"]
11 • MODEL

Why YOLOv8 Instance Segmentation?

We use YOLOv8-seg (stored as best.pt, ~54MB). YOLO stands for "You Only Look Once" — it processes the entire image in a single pass, making it fast enough for real-time use.

flowchart TD A["Image Input 640×640"] --> B["YOLOv8 Backbone CNN"] B --> C["Feature Pyramid Network"] C --> D["Detection Head"] C --> E["Segmentation Head"] D --> F["Bounding Boxes + Class + Confidence"] E --> G["Binary Masks per instance"] F --> H["We know WHAT food and WHERE"] G --> I["We know WHICH PIXELS belong to each food"] H --> J["Combined Output"] I --> J

Object Detection (Bounding Boxes)

Answers: What is it? Where is it roughly?
Draws a rectangle around each food. Good for counting items (e.g. 2 rotis), but bad for measuring liquid curries or irregular shapes.

Instance Segmentation (Masks)

Answers: Which exact pixels belong to this specific item?
Extracts an [N, H, W] mask tensor. We sum non-zero pixels to calculate the total area covered by each food item.

12 • VISION

Detection vs Segmentation — Visual Difference

flowchart LR A["📸 Meal Image"] --> B["YOLOv8-seg"] B --> C["📦 Bounding Boxes"] B --> D["🎨 Segmentation Masks"] C --> E["Food Class + Location"] D --> F["Exact Food Region"] F --> G["Sum Non-Zero Pixels = Pixel Area"] G --> H["Area Fraction = pixel_area / total_pixels"] H --> I["Weight = Area_Fraction × 4500g × Density"]
Why masks matter: A bounding box around a bowl of sambar includes the empty space around the bowl. A segmentation mask only includes the actual sambar pixels — giving us an accurate area measurement.
13 • PIPELINE

Complete AI Pipeline (What Happens Inside)

When you click "Capture & Analyze", here is exactly what happens in the backend, step by step:

flowchart TD A["📸 Base64 Image from Frontend"] --> B["Decode Base64 → Save as temp .jpg"] B --> C["model = YOLO best.pt"] C --> D["results = model temp.jpg"] D --> E["Extract result.boxes + result.masks"] E --> F["For each detection:"] F --> G["Get class_id → raw_name from model"] G --> H["Fix label: UNSCRAMBLE dict"] H --> I["true_food_name = corrected label"] I --> J["Get bounding box: x1,y1,x2,y2"] J --> K["Get mask: binary pixel array"] K --> L["pixel_area = mask.sum"] L --> M["total_pixels = H × W"] M --> N["area_fraction = pixel_area / total_pixels"] N --> O["density = get_density_factor true_food_name"] O --> P["estimated_weight = area_fraction × 4500.0 × density"] P --> Q["Simplify polygon to ~30 points"] Q --> R["Build detection object"] R --> S["Aggregate quantities dict"] S --> T["Return detections + quantities"]
Key Constants: MAX_IMAGE_WEIGHT_G = 4500.0 — This is the theoretical maximum weight if the entire camera frame was filled with density-1.0 food. It was set to 4500g to account for overhead cameras where the plate only occupies ~15-20% of the frame.

  • South Indian (sambar, rasam, pongal, avakaya)

18 • ESTIMATION

Quantity Estimation — The Area Fraction Math

This is how we convert pixels into grams. Understanding this formula is critical for the team:

flowchart TD A["YOLO outputs binary mask for each food"] --> B["pixel_area = mask.sum = count of non-zero pixels"] B --> C["total_pixels = mask_height × mask_width"] C --> D["area_fraction = pixel_area / total_pixels"] D --> E["Look up food category: get_category_for_food"] E --> F["Look up density factor from DENSITY_FACTORS"] F --> G["estimated_weight = area_fraction × 4500.0 × density_factor"] G --> H["Round to 1 decimal place"] 
# From ai_service.py — The Core Formula
pixel_area = float(mask.sum())                    # Count non-zero pixels in mask
total_pixels = float(mask.shape[0] * mask.shape[1])  # Total image pixels (H × W)
area_fraction = pixel_area / total_pixels         # What fraction of image is this food?
density = get_density_factor(true_food_name)      # Category-specific multiplier
estimated_weight_grams = round(area_fraction * MAX_IMAGE_WEIGHT_G * density, 1)
# MAX_IMAGE_WEIGHT_G = 4500.0

23 • SCORING

Meal Scoring Formula (Exactly How It Works)

flowchart TD A["Total Nutrition from All Foods"] --> B["Protein Score = min 100, Actual/Target × 100"] A --> C["Energy Score = min 100, Actual/Target × 100"] A --> D["Variety Check"] D --> E{"Has Vegetable?"} E -->|Yes| F["+25 to variety"] E -->|No| G["+0"] D --> H{"Has Fruit?"} H -->|Yes| I["+25 to variety"] H -->|No| J["+0"] K["Variety Base = 50"] --> L["Variety Score = 50 + veg_bonus + fruit_bonus"] B --> M["Final = Protein×0.40 + Energy×0.40 + Variety×0.20"] C --> M L --> M M --> N{"Score ≥ 80?"} N -->|Yes| O["🟢 PASS"] N -->|No| P{"Score ≥ 60?"} P -->|Yes| Q["🟡 REVIEW"] P -->|No| R["🔴 FAIL"] 
# scoring_service.py — The Exact Formula

protein_score = min(100, (total_protein / target_protein) * 100)
energy_score  = min(100, (total_calories / target_calories) * 100)

variety_score = 50                          # Base score
if has_vegetable: variety_score += 25       # Bonus for vegetables
if has_fruit:     variety_score += 25       # Bonus for fruit

final_score = (protein_score * 0.40)        # 40% weight
            + (energy_score  * 0.40)        # 40% weight
            + (variety_score * 0.20)        # 20% weight

# Status Thresholds
if final_score >= 80: status = "PASS"
elif final_score >= 60: status = "REVIEW"
else: status = "FAIL"
Example: A meal with 15g protein (target 20g), 500 kcal (target 650 kcal), vegetables present, no fruit → Protein: 75, Energy: 76.9, Variety: 75 → Final: 75×0.4 + 76.9×0.4 + 75×0.2 = 75.8 → REVIEW

25 • RECOMMENDATIONS

Automated Recommendations

🥗 Protein Deficit

If Protein Score < 80%: "Increase pulse/protein component (e.g. add ~30g dal)."

⚡ Energy Deficit

If Energy Score < 80%: "Increase main carbohydrate portion (e.g. rice or roti)."

🥬 No Vegetables

26 • SIMULATION

What-If Simulator

The What-If Simulator lets users adjust food quantities (dal, vegetables) using sliders and instantly see how the score changes. It uses the real backend formula with the following assumptions:

  • 150g rice is already on the plate (195 kcal, 4.05g protein)
  • Age group: 11-14 (Target: 650 kcal, 20g protein)
  • Vegetables are present (+25 variety bonus), no fruit assumed
How it works: Dal slider (10-200g) and Vegetable slider (10-150g) adjust the inputs. The formula recalculates Protein Score, Energy Score, and Variety Score to show the final score in real-time.

37 • ROBUSTNESS

Edge Cases & How We Handle Them

🔴 No Image Provided

Backend returns a dummy detection (250g rice) as fallback for demo mode.

🔴 No Face Detected

Returns face_detected: false and shows "No face detected" error.

🔴 Unknown Age Group

Falls back to "11-14" age group as default.

🔴 Low Confidence Detection

Still included in results — frontend can filter/warn.

🔴 Overlapping Foods

YOLO handles via NMS (Non-Maximum Suppression).

🔴 Empty Plate

No detections → empty quantities → score = 10 (base variety only).

39 • HONESTY

Known Limitations

  • Quantity is estimated from 2D pixel area, not physically weighed — accuracy depends on camera angle and distance.
  • Similar-looking foods (e.g. sambar vs rasam) can be confused by the model.
  • Poor lighting significantly reduces detection quality and confidence.
  • Overlapping or occluded food items may be partially detected.
  • Nutrition values are based on generic category averages, not exact recipe analysis.
  • Face recognition requires good lighting and front-facing position.
  • CSV storage is not suitable for production scale (thousands of concurrent users).
  • The density factor approach is a rough approximation — a depth camera would improve accuracy.
  • This is a monitoring/screening prototype, not a laboratory food-safety test.

One-minute elevator pitch:
AI MealGuard is an AI-powered school meal monitoring system designed around SDG 2 — Zero Hunger. A student is identified by ID or facial recognition. Their meal plate is photographed and analyzed by a YOLOv8 instance segmentation model trained on 50 Indian food classes. The system extracts pixel-level masks, estimates approximate weights using area-fraction math and density factors, calculates total nutrition from a verified database, compares it against ICMR-NIN age-group benchmarks, generates a weighted score (Protein 40% + Energy 40% + Variety 20%), explains exactly what's missing, recommends specific improvements, and stores everything in a historical database for analytics. The full stack includes a Tailwind CSS frontend with facial recognition, a FastAPI backend with 9 endpoints, CSV-based persistence, and Docker deployment.
